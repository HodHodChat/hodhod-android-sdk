# Architecture

```
┌────────────┐   configure/open/identify   ┌───────────────────────────┐
│  Your app  │ ───────────────────────────▶│ hodhod-ui (Compose)        │
└────────────┘                             │ HodhodChatActivity / HodhodChat / HodhodBubble
                                           │ Home · Chat · Tickets · Pre-chat · CSAT · FlowRunner
                                           └──────────────┬────────────┘
                                                          │ HodhodRepository (StateFlow / SharedFlow)
                                           ┌──────────────▼────────────┐
                                           │ hodhod-core (no UI)        │
                                           │ Hodhod · DefaultHodhodRepository · WidgetApi (OkHttp)
                                           │ CableClient (ActionCable over WebSocket)
                                           │ SessionStore (EncryptedSharedPreferences)
                                           │ DefaultFlowEngine (chatbot flows) + analytics
                                           └──────────────┬────────────┘
                                                          │ HTTPS  /api/v1/widget/*, /cable
                                                  Hodhod server (same API as the web widget)
```

## Modules

| Module | Contents |
|---|---|
| `hodhod-core` | Public API (`Hodhod`, `HodhodConfig`, `HodhodUser`, `HodhodRepository`, models, `HodhodI18n`, `FakeHodhodRepository` for previews/tests). Everything under `chat.hodhod.sdk.internal` is private to the SDK. |
| `hodhod-ui` | Compose screens, the theme (the web widget "Masir" look), strings generated from the widget locale files (`tools/gen_strings.py`), the chat activity. Depends on core through `api(...)`. |
| `sample` | Demo app (configure form, identify, open chat). Build types: `debug`, `release` (R8 minified, debug-signed), `qa` (minified + cleartext to `10.0.2.2` for local testing). |

## Data flow

* **Bootstrap**: `POST /api/v1/widget/config` (inbox settings, auth token, pubsub token, contact mode, ticket form, categories, holidays, `lock_to_single_conversation`, `has_flow_bot`). Older servers that lack the extra fields are handled by reading `window.chatwootWebChannel` from `GET /widget`.
* **Live updates**: ActionCable `RoomChannel` subscription with the pubsub token. The socket is open only while the app is in the foreground; on return to the foreground the repository re-syncs missed messages. Reconnects use jittered exponential backoff. There are no push notifications: the unread count only updates while the app runs.
* **Optimistic sending**: a message has a stable `key` (client id) from the optimistic state to the server copy; failed sends can be retried or discarded.
* **Conversation lifecycle**: `None` (home) -> `Active` -> `Ended` (end screen with survey) -> `resetConversation()` -> `None`. With `lock_to_single_conversation` a resolved conversation stays `Active` and a new message reopens it.
* **Contact modes**: `WidgetConfig.startMode(now)` decides chat / ticket / choice (`chat`, `ticket`, `both`, `ticket_when_offline` using working hours and holidays).
* **My tickets**: `GET /api/v1/widget/tickets?status=open|closed|all&page=&per_page=` returns the visitor's tickets (all sources, every contact mode) plus `meta` counters; `GET /api/v1/widget/tickets/summary` feeds `HodhodRepository.ticketSummary` (Home badge). Visibility follows the HMAC-verified contact inboxes of the widget API. Missing `meta`/summary (older servers) falls back to client-side counting, filtering and paging. A ticket whose conversation is the current chat (`conversation_display_id`) opens the chat instead of the ticket thread, and its messages stay in the chat.
* **Announcements**: `website_channel_config.announcements` of the bootstrap response (max 2, server-filtered by enabled + schedule) is parsed tolerantly into `WidgetConfig.announcements` (unknown block types dropped; only `http`/`https`/`mailto`/`tel` links and https images kept). `HodhodRepository.announcements` is that list minus the dismissed ones; dismissals are persisted in the session store as `websiteToken:id:updated_at` keys (bounded to 50), so an edited announcement (new `updated_at`) is shown again and re-reading the config on every refresh picks up schedule changes. The UI renders them at the top of the scrolling start screens (Home, ticket panel acting as Home, pre-chat) before the incident notices; links go through `ACTION_VIEW` with the same scheme allow-list again.
* **Chatbot flows**: `GET /api/v1/widget/chatbot_flow` returns the stored graph; the engine (a Kotlin port of the web engine, 17 node kinds) runs client-side. Handoff to a live agent or a ticket posts the same payloads as the web widget, and analytics events go to the same ingestion endpoint. Parity with the web engine is tested with fixtures generated by the real JS engine (`tools/gen_flow_parity.mjs`, `hodhod-core/src/test/resources/flow-parity`).
* **Security**: HTTPS is required unless `allowCleartext`; tokens are stored in EncryptedSharedPreferences; nothing is logged unless `enableLogging`; attachments from the camera go through a `FileProvider` whose authority is `${applicationId}.hodhod.fileprovider`.

## Testing

```
./gradlew :hodhod-core:testDebugUnitTest :hodhod-ui:testDebugUnitTest lint
```

`LocalServerIntegrationTest` talks to a local Hodhod server and is skipped automatically when `/tmp/lark-seed/android-core-it.json` is missing (it holds website tokens and an agent token for the seed inboxes).
